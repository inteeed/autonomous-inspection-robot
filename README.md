# Autonomous Industrial Inspection Robot

ROS 2 Humble package for a TurtleBot3 Waffle Pi inspection robot. The project
simulates an industrial inspection workflow in Gazebo Classic, detects ArUco
markers, follows inspection waypoints, logs reports, and can run an optional
dashboard/anomaly/scheduler stack.

**Authors:** Izzatbek & Boburjon

## What It Does

1. Starts a custom Gazebo inspection world with TurtleBot3 Waffle Pi.
2. Drives through configured inspection waypoints with either a simple waypoint
   follower or Nav2.
3. Detects ArUco markers from the robot camera and publishes JSON detections.
4. Optionally checks marker image regions for visual anomaly signals.
5. Writes inspection reports to `~/inspection_reports`.
6. Optionally serves a live dashboard at `http://localhost:8080`.

## ROS Package

The ROS package is `inspection_robot`, implemented as an `ament_python` package
under `ros2_ws/src/inspection_robot`.

Console scripts installed by `setup.py`:

| Executable | Source file | Purpose |
|---|---|---|
| `aruco_detector` | `inspection_robot/aruco_detector.py` | Detects ArUco markers, publishes detections, and can publish annotated images |
| `waypoint_follower` | `inspection_robot/waypoint_follower.py` | Drives the robot through YAML waypoints with scan-based obstacle handling |
| `nav2_waypoint_follower` | `inspection_robot/nav2_waypoint_follower.py` | Sends waypoints to Nav2 using the `NavigateToPose` action |
| `anomaly_detector` | `inspection_robot/anomaly_detector.py` | Checks marker ROIs for simple color/edge anomaly signals |
| `inspection_scheduler` | `inspection_robot/inspection_scheduler.py` | Publishes scheduled run requests and marker skip hints |
| `dashboard_server` | `inspection_robot/dashboard_server.py` | Serves inspection events over HTTP server-sent events |
| `report_logger` | `inspection_robot/report_logger.py` | Aggregates detections/anomalies and writes JSON, CSV, and PDF reports |

Helper modules:

| File | Purpose |
|---|---|
| `inspection_robot/waypoint_state_machine.py` | Shared waypoint and obstacle-state logic |
| `inspection_robot/report_utils.py` | Report formatting and PDF helper logic |

## Launch Files

| Launch file | Main use | Important arguments |
|---|---|---|
| `bringup.launch.py` | Gazebo simulation with simple waypoint follower, detector, logger, and optional RViz | `use_sim_time`, `publish_annotated`, `use_rviz` |
| `bringup_nav2.launch.py` | Gazebo simulation with SLAM/localization, Nav2, detector, Nav2 waypoint follower, and logger | `use_sim_time`, `use_slam`, `map` |
| `bringup_hw.launch.py` | Hardware path for TurtleBot3 bringup, camera, Nav2, detector, waypoint follower, and logger | `use_slam`, `map`, `autostart`, `camera_package`, `camera_executable` |
| `inspection_intelligence.launch.py` | Optional anomaly detector, scheduler, and dashboard server | `use_sim_time` |

## Config And Assets

| Path | Contents |
|---|---|
| `config/waypoints.yaml` | Six route targets: five marker approaches plus `return_home` |
| `config/camera_sim.yaml` | Simulated TurtleBot3 camera calibration |
| `config/camera_hw.yaml` | Hardware camera calibration placeholder |
| `config/camera_calibration.yaml` | Alternate Gazebo camera calibration format |
| `config/nav2_params.yaml` | Nav2 parameters for simulation |
| `config/localization.yaml` | Hardware localization parameters |
| `config/slam_toolbox.yaml` | SLAM Toolbox mapping parameters |
| `config/scheduler.yaml` | Inspection scheduler timing and skip-window parameters |
| `config/anomaly.yaml` | ROI anomaly threshold parameters |
| `worlds/inspection.world` | Gazebo inspection arena |
| `models/aruco_marker_0` through `models/aruco_marker_4` | Gazebo marker models, material scripts, and PNG textures |
| `rviz/inspection.rviz` | RViz view for the annotated inspection image stream |

The marker textures are already present. To regenerate the Gazebo marker assets:

```bash
cd ros2_ws
python3 src/inspection_robot/scripts/generate_world_assets.py
```

## Prerequisites

- ROS 2 Humble
- Gazebo Classic 11
- TurtleBot3 packages:
  `turtlebot3_gazebo`, `turtlebot3_description`, `turtlebot3_bringup`
- Nav2 and SLAM packages:
  `nav2_bringup`, `nav2_msgs`, `slam_toolbox`
- Camera/vision packages:
  `cv_bridge`, `gazebo_ros`, `v4l2_camera`
- Python packages used by the code/tests:
  `opencv-python` or system OpenCV with ArUco support, `pyyaml`, `pytest`

On Ubuntu with ROS Humble packages, the Dockerfile shows the expected apt
dependencies.

## Build

From this repository root:

```bash
source /opt/ros/humble/setup.bash
cd ros2_ws
colcon build --packages-select inspection_robot
source install/setup.bash
```

## Run In Simulation

Simple waypoint follower:

```bash
cd ros2_ws
source install/setup.bash
ros2 launch inspection_robot bringup.launch.py
```

With RViz:

```bash
ros2 launch inspection_robot bringup.launch.py use_rviz:=true
```

Nav2 with SLAM mapping:

```bash
ros2 launch inspection_robot bringup_nav2.launch.py use_slam:=true
```

Nav2 localization against a saved map:

```bash
ros2 launch inspection_robot bringup_nav2.launch.py use_slam:=false map:=/path/to/map.yaml
```

Optional intelligence stack:

```bash
ros2 launch inspection_robot inspection_intelligence.launch.py
```

Dashboard:

```text
http://localhost:8080
```

## Run On Hardware

The hardware launch starts TurtleBot3 bringup, a camera node, Nav2
localization/navigation, ArUco detection, the Nav2 waypoint follower, and report
logging.

```bash
cd ros2_ws
source install/setup.bash
ros2 launch inspection_robot bringup_hw.launch.py map:=/path/to/map.yaml autostart:=false
```

Defaults:

- `camera_package:=v4l2_camera`
- `camera_executable:=v4l2_camera_node`
- `use_slam:=false`
- `autostart:=false`

Before a real run, replace `config/camera_hw.yaml` with the calibrated camera
parameters for the hardware camera.

## Topics And Outputs

Main topics:

| Topic | Type | Producer/consumer |
|---|---|---|
| `/inspection/detections` | `std_msgs/String` JSON | `aruco_detector` to logger/dashboard/anomaly detector |
| `/inspection/annotated` | `sensor_msgs/Image` | annotated camera stream from `aruco_detector` |
| `/inspection/status` | `std_msgs/String` JSON/status | waypoint followers to dashboard/scheduler |
| `/inspection/anomalies` | `std_msgs/String` JSON | `anomaly_detector` to logger/dashboard |
| `/inspection/run_request` | `std_msgs/Bool` | scheduler to waypoint followers |
| `/inspection/skip_markers` | `std_msgs/String` JSON | scheduler to waypoint followers |
| `/inspection/run_done` | `std_msgs/Bool` | waypoint followers to `report_logger` |
| `/cmd_vel` | `geometry_msgs/Twist` | simple waypoint follower to robot base |

Reports are written under:

```text
~/inspection_reports/run_YYYYMMDD_HHMMSS/
```

The logger writes `report.json`, `report.csv`, and, when enabled, `report.pdf`.
Anomaly snapshots are saved under:

```text
~/inspection_reports/anomalies/
```

## Tests And CI

Run the lightweight Python tests:

```bash
cd ros2_ws/src/inspection_robot
pytest test/ -v
```

Run ROS package tests after building:

```bash
cd ros2_ws
colcon test --packages-select inspection_robot
colcon test-result --verbose
```

CI workflows:

- `.github/workflows/ci.yml` runs pytest and flake8.
- `.github/workflows/colcon.yml` runs ROS Humble colcon build/test through
  `ros-tooling/action-ros-ci`.

## Docker

Build the Humble image:

```bash
docker build -t inspection_robot .
```

Run the default simulation launch:

```bash
docker run --rm -it --net=host inspection_robot
```

For Gazebo GUI use, pass through the host display as appropriate for your Linux
desktop environment.
